# Developer guide

## Repository layout

```
app/                    the Android app (Expo / React Native, TypeScript)
├── App.tsx             main screen
├── components/         map view (Leaflet in a WebView), settings, compass, UI kit
├── hooks/              sensors → engine → React state; persisted settings
├── lib/nav/            navigation engine: pure TypeScript, unit-tested, runs under Node
├── lib/mapPack.ts      the embedded map (reads map-pack/map.json)
├── modules/rotation-vector/   native Android module (orientation fusion)
├── plugins/withMapAssets.js   copies the map tiles and Leaflet into the Android assets
├── scripts/            replay.ts, simulate.ts (desktop tools)
└── map-pack/           generated by the map kit, not versioned
mapkit/                 the map kit (Python): image → tiles + wall mask
maps/demo/              the demo map (public domain), the only versioned map
docs/                   documentation, including the technical report
build.sh                builds a map pack and the APK
```

The engine in `app/lib/nav/` has no dependency on React Native: the app, the unit tests and the
replay tool all run the same code. The [technical report](technical-report.md) describes the
algorithms.

## Prerequisites

* **Node.js** ≥ 20.19 and npm
* **Python** ≥ 3.10 with `numpy`, `pillow`, `scipy` (`pip install ./mapkit`)
* **JDK 17** (Gradle 8.13 rejects recent JDKs; `build.sh` picks a JDK 17 automatically when one
  is installed under `/usr/lib/jvm`)
* **Android SDK** (the easiest way is to install Android Studio), with `ANDROID_HOME` set
* An **Android phone** with USB debugging enabled, or the Android emulator (no real sensors,
  though)

```bash
git clone https://github.com/HueyNemud/GPSnt.git
cd GPSnt/app && npm ci && cd ..
pip install -e './mapkit[test]'
```

The native module (`modules/rotation-vector`) means **Expo Go cannot run GPS'nt**: you need a
build that contains it, as described below.

## Day-to-day development: QR code and live reload

1. **Once** (and again only when native code changes: `app/modules/`, a native package,
   `app/app.json`, or **the map**):

   ```bash
   ./build.sh --dev [--map maps/my-map]
   ```

   This builds a development APK (`expo-dev-client`), a kind of "Expo Go" that contains the native
   module and the map tiles. It is installed automatically if the phone is plugged in with USB
   debugging; otherwise copy `dist/gpsnt-dev.apk` to the phone.

2. **Each session**:

   ```bash
   cd app
   npm run dev          # phone on the same Wi-Fi network as the computer
   npm run dev:tunnel   # otherwise (guest network, mobile data…)
   ```

   Scan the QR code with the phone camera, or open GPS'nt on the phone: the JavaScript is loaded
   from the computer and reloaded on every save.

The development and release APKs are the same app (`io.github.hueynemud.gpsnt`): installing one
replaces the other, settings are kept.

## Standalone build

```bash
./build.sh [--map maps/my-map]
```

The JavaScript is embedded: the APK works with no computer and no network. It is copied to
`dist/gpsnt-<version>-<map id>.apk`.

> **Signing.** Release APKs are currently signed with Expo's default debug key. That is fine for
> sideloading, but Android refuses to update an app signed with a different key: an APK built on
> another computer (or by someone else) cannot replace yours without uninstalling it first, which
> also deletes its settings.

## Tests

```bash
cd app && npm test && npm run typecheck   # engine unit tests, TypeScript
cd mapkit && pytest                       # map kit
```

The TypeScript type check needs a map pack in `app/map-pack` (`./build.sh` makes one, or run
`PYTHONPATH=mapkit python3 -m gpsnt_mapkit build maps/demo`). Continuous integration
(`.github/workflows/ci.yml`) runs all of the above on every push and pull request.

## Recording, replaying, simulating

Tuning the engine on the field is slow. Instead, record the raw sensor stream once and replay it
at the desk as many times as needed:

1. In the app: *Settings → Record sensors*, walk (making a few fixes: they serve as ground truth),
   then *Stop and export recording* and send the JSON file to your computer.
2. Replay it through the same engine, possibly with other parameters:

   ```bash
   cd app
   npm run replay -- gpsnt-recording-XXXX.json [--pack map-pack] [--no-walls] [--k 0.5] \
                     [--ppm 2.6] [--north 0] [--decl 1.5] [--seed 1] [--out trace.json]
   ```

   It prints the error measured at each fix, the learnt bias and step scale, and writes the
   estimated trace.

No field data? Generate a synthetic walk on the demo map:

```bash
npm run simulate -- --out walk.json [--bias 8] [--fixes] [--path "x,y x,y …"]
npm run replay -- walk.json
```

## Troubleshooting

* **"Android orientation fusion unavailable"**: the app is running in Expo Go, or on iOS. Use a
  development build (`./build.sh --dev`).
* **`adb devices` shows "unauthorized"**: unplug the cable, revoke the authorisations
  (*Developer options → Revoke USB debugging authorisations*), plug it again and accept the
  prompt, ticking *Always allow*.
* **Gradle complains about the Java version**: install a JDK 17 or point `JAVA_HOME` to one.
* **"No map pack in app/map-pack"** during the build: run `./build.sh` rather than
  `npx expo run:android`, or build a pack first (see above).

## Releasing

1. Update `CHANGELOG.md` and the version in `app/app.json`, `app/package.json` and
   `mapkit/gpsnt_mapkit/__init__.py`; increase `android.versionCode` in `app/app.json`.
2. `./build.sh` (demo map) and test the APK on a phone.
3. Tag `vX.Y.Z`, push the tag and create a GitHub release with `dist/gpsnt-X.Y.Z-demo-1.apk`
   attached.
